| `AudioEngine`'s coroutine scope must specify `Dispatchers.Main` explicitly | 2026-08-11 | **Real crash, found via first-ever real-device test** (a Samsung Galaxy S24 Ultra connected over USB) — every previous "verified" build only meant `assembleDebug`/`lintDebug` passed, never that the app actually ran. `AudioEngine`'s scope was `CoroutineScope(SupervisorJob())` with no dispatcher, which defaults to `Dispatchers.Default` (a background pool). ExoPlayer's `Player` interface requires all access — including the `.volume` get/set inside `fadeTo()` — on the main thread; violating that throws `IllegalStateException: Player is accessed on the wrong thread` and crashes immediately on the very first fade (i.e. the first `play()` call, i.e. essentially immediately after tapping Demo or Start Mission). Fixed by adding `Dispatchers.Main` to the scope, matching the pattern `MissionEngine` already used correctly. Confirmed fixed on-device: Demo now runs past the point that used to crash with zero `FATAL EXCEPTION`s in logcat. This bug had been latent since `AudioEngine.kt` was first written — nothing in Gradle's build/lint pipeline can catch a runtime threading violation like this, only actually running the app can. |
